# Simulation typée et erreurs de journalisation

C3-01 : le runtime fournit maintenant les exemples manquants selon le type déclaré et les conditions reliées. Les exemples explicitement configurés restent prioritaires ; une valeur explicitement invalide demeure refusée. Le résultat conserve le marquage SIMULATION, aucune commande ni IA n’est exécutée, les décisions humaines restent attendues. Sept tests ciblés vérifient types, deux branches booléennes, valeurs explicites et refus de coercition.

C3-04 : le terminal de lancement peut fermer ses lecteurs stdout/stderr alors que la fenêtre reste ouverte. Une erreur métier rejetée par IPC devient alors une exception native dans le logger Electron. Reproduction réelle sur le paquet gelé : test desktop-output-pipes, sortie EPIPE, stack replyWithError identique à la capture du testeur. Le dialogue natif est intercepté et enregistré par le banc pour éviter de bloquer les tests ; la présence de toute exception fait échouer le test. Aucun état client utilisé.

Le point d’entrée Electron installe un gestionnaire ciblé des erreurs EPIPE sur stdout/stderr avant le chargement de l’application. Les autres erreurs restent levées ; aucun gestionnaire global qui masquerait les bugs. Deux tests Node incluent une vraie fermeture de pipes et le maintien des autres erreurs. La reproduction initiale avec console Node seule ne reproduisait pas l’erreur (Node la masque) ; elle n’est pas retenue comme preuve. La contre-épreuve Electron source est reçue : erreur métier récupérée, second projet créé, navigation fonctionnelle et aucune exception native. Le paquet final devra encore être vérifié après reconstruction.
