# Reprise et erreurs fournisseur

C1/C5 : le terminal reconnaissait le shell après arrêt de l’agent, mais le suivi attendait un nouvel appel à Ouvrir le terminal pour le savoir. L’intégration observe maintenant les sessions de la conversation affichée sans changer leurs processus ni leurs états moteur. Le suivi affiche Agent arrêté · progression conservée et propose la reprise explicite existante.

Huit recettes d’interaction passent, dont le nouveau parcours : arrêt via terminal, état affiché sans nouvelle ouverture, annulation du dialogue de reprise sans relance, reprise explicite, même session/PID, demandes identiques et question toujours attendue. Le processus IA est un programme local déterministe : aucune qualité fournisseur qualifiée.

C4 a également révélé une erreur de décodage brute lorsque le programme inerte répondait hors protocole. Huit réponses invalides réellement produites par un processus Python local (flux mal formé, champ JSON invalide, événements non objets ou champs de forme incompatible) sont reproduites dans un test à sous-cas. Le message explique désormais format attendu, connexion, modèle/version et reprise ; le résultat reste en échec, la décision aval n’est pas libérée et les journaux fournisseurs temporaires sont nettoyés. Rouge/vert conservés séparément. Les erreurs JSON/encodage sont traduites et les formes des événements utilisés sont contrôlées explicitement. Les autres erreurs de programmation restent visibles ; aucun succès fabriqué. Le relecteur indépendant a reproduit puis reçu les événements null/liste/nombre/texte et item absent, ainsi que les outils Claude invalides sans affaiblir le refus des outils hors périmètre.
