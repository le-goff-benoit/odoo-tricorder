## Constats à corriger

**D1 — Source de passation réservée au JSON — gravité moyenne, manque UX.** Reproduction : valider un résultat d’une demande globale ; « Transférer vers un projet… » ; créer le brouillon dans un projet. Attendu : voir la demande d’origine, ouvrir son suivi et lire le résultat transmis. Observé : le message temporaire « Brouillon créé avec sa source globale » disparaît ; ni l’éditeur ni les paramètres ordinaires n’affichent la source. Elle n’apparaît qu’après Paramètres du workflow → Paramètres supplémentaires → Paramètres (objet JSON). [Capture](captures/14-transfert-source-json.png). Le résultat est conservé, pas perdu. Prochaine action : ajouter un résumé lisible « Issu de… », un lien au suivi source et les résultats transmis, avec leur portée.

**D2 — État archivé invisible sur les cartes — gravité faible, manque UX.** Reproduction : archiver un workflow/projet, afficher les archives, ouvrir l’élément. Attendu : reconnaître immédiatement un élément archivé. Observé : même titre, mêmes boutons usuels ; seul le menu « Restaurer » ou « Restaurer le projet » révèle l’état. [Workflow](captures/10-workflow-archive-actions.png), [projet](captures/12-projet-archive-sans-badge.png). Prochaine action : afficher un badge « Archivé » sur carte et en-tête, en conservant les actions de consultation/restauration.

Le changement de modèle après saisie du nom a remplacé le nom dans le formulaire de création ; ce geste n’est pas retenu comme bug confirmé. La capture 01 documente seulement ce point exploratoire.

## Limites et isolation du banc

- Interface réelle sur le paquet figé via Electron/Playwright et Shadow DOM. Dialogues natifs de fichiers remplacés uniquement par le retour d’un chemin synthétique ; import, export, choix de dépôt et écritures de définition exécutés par l’application.
- HOME, XDG, CODEX_HOME, CLAUDE_CONFIG_DIR, état et runtime entièrement neufs ; environnement en liste blanche, `DISPLAY=:182`, PATH strict des stubs puis `/usr/bin:/bin`. Codex **et** Claude vérifiés avant premier broker : [précontrôle](stub-preflight.txt). Le terminal réel montre le marqueur `SYNTHETIC_PASSATION_STUB codex INERT` : [capture](captures/04-original-nord-terminal-inerte.png).
- Les fournisseurs sont inertes. Pour disposer de résultats et d’une preuve à transmettre, les seules fixtures d’exécution passent par `Engine.claim`, `submit`, `artifact` du backend empaqueté, sous `STATE_DIR/workflows`. Tous les examens de résultat et l’accord Nord ont été faits dans l’interface. Aucun JSON/SQLite d’état n’a été retouché. Les comparaisons finales emploient des lectures `Engine.run/runs`.
- Une décision humaine générique a été exercée ; aucune autorisation d’effet externe, connexion réseau, fournisseur réel ou opération de production n’est qualifiée. Les clones/commits concernent uniquement les dépôts locaux synthétiques ; aucun commit du dépôt application.
- Aucun build ni suite globale. Seize captures distinctes maximum. L’application et ses brokers ont été fermés ; aucune commande restante ne référence le répertoire synthétique : [nettoyage](cleanup.json). Le contexte temporaire est conservé comme fixture reproductible, sans processus actif.

Les réserves D1 et D2 ont été transmises au responsable avant ce rapport. Les cinq parcours sont réceptionnés avec ces réserves.
