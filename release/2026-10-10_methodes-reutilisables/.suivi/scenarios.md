# Parcours de réception

Les anciennes preuves rc.17 servent de référence technique, pas de réception UX.
Les nouveaux essais distinguent première compréhension, comportement du moteur
avec fournisseurs de test et analyse réellement effectuée par une IA.

| Parcours | Situation / résultat attendu | Preuve utile |
|---|---|---|
| Consulter | Ouvrir support et réunion sans copie ; expliquer source, étapes, agents, résultat et limites. | Captures visibles ; nombres de workflows/runs inchangés. |
| Abandonner | Choisir un modèle, continuer puis fermer avant lancement. | Aucun workflow supplémentaire ; brouillon annoncé s’il est conservé. |
| Bibliothèque | Chercher une méthode de support sans recevoir blocs Communication/Analyse ou démonstration. | Vue par défaut et recherche ; composants accessibles depuis composition. |
| Source texte | Coller demande support longue avec échéance, distinguer faits/urgence/nature. | Contexte transmis à la bonne exécution ; pas de référence à des réunions. |
| Source fichier | Joindre deux documents, préciser leur relation aux réunions, modifier les originaux après import. | Copie conservée fidèle, noms/source identifiables ; aucune lecture distante annoncée. |
| Source externe | Donner recherche email ou lien avec accès indisponible. | La référence reste « à récupérer » ; demande de contenu, aucune prétention d’email lu. |
| Création | Décrire objectif, première analyse, rédaction et relecture conditionnelle sans saisir port/clé/type. | Contrats valides et données transmises, entièrement construits dans GUI. |
| Parallèle | Deux travaux indépendants puis synthèse. | Les deux peuvent être prêts ; synthèse attend tous les résultats requis. |
| Décision | Demander une précision qui détermine le périmètre. | Aucun travail dépendant avant réponse ; refus ne libère pas la branche approuvée. |
| Agent | Choisir un rôle, examiner sa consigne, ajouter un pack dans un contexte. | Rôle résolu à l’exécution ; modèles et outils distingués ; historique figé. |
| Suivi | Agent arrêté, question en attente et échec de tâche. | Cause/prochaine action visibles sans interpréter terminal ; saisie non interrompue par polling. |
| Résultat | Réunion avec compte rendu, actions et email ; support avec réponse. | Tous les livrables annoncés présents, copiables ; brouillon local/distant distingué. |
| Rapport | Plan et actions longs à largeur réduite puis normale. | Première colonne lisible et défilement contenu ; journal accessible après synthèse. |
| Répétition | Nouvelle demande après succès ou abandon ; personnaliser modèle. | Réponses neuves ou reprise volontaire annoncée ; exécutions précédentes inchangées. |
| Planification | Configurer fréquence et source fixe/renouvelée depuis méthode enregistrée. | Réponses visibles, remplacement annoncé ; pas de récupération de fichier nouveau inventée. |

Le panel de réception consigne le résultat réellement observé, y compris les
abandons et capacités manquantes. Il n’est pas invité à déclarer « adoption »
parce que le script passe. Une difficulté importante rencontrée sur le nouveau
candidat doit être corrigée ou conservée explicitement avec sa conséquence.
