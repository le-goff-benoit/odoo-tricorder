# 0.3.2 — Des preuves de qualité cohérentes

Un rapport JUnit contenant un test détaillé réussi et une autre suite résumée
en échec pouvait apparaître vert. Les compteurs sont désormais confrontés aux
résultats de chaque suite. Les rapports contradictoires restent visibles comme
non exploitables ; les suites imbriquées cohérentes ne sont pas comptées deux fois.

Cette correction accompagne la boucle d’essais Odoo Crew : une terminaison d’agent,
un test réussi et une tâche reçue sont trois informations distinctes.
Aucun appel modèle ni accès à un projet client dans les tests du Tricorder.

Contrôles locaux : 87 tests Python, 56 tests Node, 16 parcours Electron réussis
(1 test de projet réel volontairement ignoré), mêmes 16 parcours dans le paquet,
et construction Debian réussie. Les cas du lecteur JUnit sont synthétiques.

Révision Crew fixée en CI : `f11913d1bf9896e32286b0e24bed041984bc8b60`.
Installation locale vérifiée : version 0.3.2, archive app.asar et lecteur qualité
identiques au paquet testé ; parcours sur l’exécutable installé réussi.
